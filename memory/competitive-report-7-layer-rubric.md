用户提供的竞品分析报告评价框架，7 层（低分→高分）：

1. **分析边界**：泛泛介绍产品 → 明确说明分析范围和排除项（如"Cursor 代码补全体验"应聚焦补全准确性/延迟/上下文/跨文件/Tab交互/下一步预测/迁移成本/企业适配，而非整个 Agent 能力）
2. **竞品选择**：随便列竞品 → 按竞争类型分层（直接对手/插件型/IDE原生/企业安全）并解释各抢什么场景
3. **分析维度**：只比功能有无 → 比贴近用户决策的竞争逻辑（是否自然触发/理解上下文/预测下一步/低干扰/适合企业库）
4. **证据质量**：无来源或混杂 → 官方/用户反馈/第三方评测/实测数据分层，每条结论可溯源(evidence_id)
5. **事实vs推断**：混在一起 → 明确区分 fact / inference，不过度推断
6. **战略洞察**：功能摘要 → 说明各产品真实竞争点（Cursor抢AI原生入口/Copilot抢GitHub分发/Windsurf抢编辑流/Supermaven抢低延迟大上下文/JetBrains抢专业IDE语义/Tabnine抢企业采购）
7. **建议落地**：空泛口号 → 有对应痛点+证据+预期收益+优先级+验收指标+实施难度

一句话标准：好报告不是"资料更全"，而是"判断更准、证据更硬、建议更能落地"。
