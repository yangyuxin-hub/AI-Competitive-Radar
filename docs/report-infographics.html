End-to-end Agent Workflow

从一句需求到可溯源竞品报告

把“LLM 写报告”拆成规划、采集、分析、成文、质检五段工程链路；每段都有输入、产物、质量门和失败处理。

01

Intake

解析目标产品、竞品、分析焦点、用途；信息不足时生成澄清问题。

02

Planner

把意图转成必需 claim type 与 evidence tasks，明确采集验收口径。

03

Collector

live -> cache -> mock 三层兜底，采集 raw_evidence 与覆盖审计。

04

Analyzer

facts -> derivations 两步分析，产出 feature、pricing、SWOT、建议。

05

Writer

按 schema 渲染 Markdown；关键结论句末写入证据 chip。

06

Reviewer

R0-R10 规则质检；通过、精准打回或分层降级。

输入
  • 自然语言需求：分析 X 与 Y 在 Z 维度的差距
  • 配置：products / domains / scoring / prompts
  • 运行模式：fast / balanced / deep
关键契约
4

3
采集降级：live / cache / mock
2
Analyzer 两步：facts / derivations
R0-R10

输出
  • 结构化竞品报告：功能矩阵、定价、痛点、SWOT、建议
  • 质量报告：score、errors、warnings、reject target
  • 证据抽屉：snippet、URL、source bias、reliability
Reviewer 发现问题 -> 按 collector / analyzer / writer 精准打回；重试耗尽 -> degraded_writer 诚实降级

Project Value & Technical Highlights

把竞品分析做成可复用的 Agent 工程系统

项目价值不只在“生成一篇报告”，而在于把行业分析沉淀成可配置、可质检、可复盘、可跨场景迁移的工作流。

原始痛点
慢
  • 人工搜集、整理、对比、写报告耗时长
  • 不同人输出结构不一致，复用困难
散
  • 官网、社区、定价页、用户反馈分散
  • 证据和结论通常脱节，事后难审计
虚
  • LLM 直接写报告容易编造引用
  • 缺少质量门，无法判断能不能发出去
系统方案
规划Evidence Planner 把用户意图变成必需证据类型和采集任务。
采集Collector 三层降级，保证 live 不稳定时仍能跑完 Demo 闭环。
分析Analyzer 拆 facts / derivations，两步降低截断和倒推式幻觉。
溯源每条结论引用确定性 evidence_id，报告正文统一渲染 chip。
质检Reviewer R0-R10 检查引用、结构、建议、正文 chip 和内部字段泄漏。
观测StageReport 汇总每段“过了吗 / 哪里坏 / 怎么修”，支撑时间线和控制面演进。

业务价值
PM 可更快拿到结构化竞品判断，并直接看到每条结论依据。
工程价值
报告质量从 Prompt 经验变成可测试、可打回、可复盘的流程。
可信价值
采不到就标 unknown / degraded，不为了“看起来完整”硬编数据。
