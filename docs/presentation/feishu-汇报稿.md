# 竞品雷达 · 答辩汇报稿（25′ 陈述）

> 项目：AI Competitive Radar —— 面向企业 PM / 数据分析师的**可观测、可量化、可修复**竞品分析 Agent 协作系统。
> Demo：输入「分析 Cursor、Windsurf、GitHub Copilot 在代码补全体验上的差距」→ 输出每条结论可溯源的结构化竞品报告。
> 形式：25′ 陈述（背景 / 核心技术 / Demo）+ 20′ 问答。

---

## 0. 全场主线（开场抛、结尾收）

> **做这个项目，搭一个能跑的 Demo 我很快就做好了。真正难、也是我大部分精力花的地方，是把最终报告的质量做上去——而这要求我对每一个环节都完全可观测、可控。所以我做的核心，是把竞品分析拆成可审计的阶段，给每个阶段定义清楚该输出什么，再用可观测性检查它实际输出了什么，发现偏差就修。这个项目的主角不是大模型，是可观测性。**

---

## 1. 主线导览：从一句需求到可信报告

一条直线流水线，所有功能、架构、难点都挂在这条线上：

```
一句分析需求
  → 证据规划   (Evidence Planner)
  → 多源采集   (Collector / EvidenceService)
  → 结构化分析 (Analyzer：facts → derivations)
  → 报告生成   (Writer，每条 claim 绑定 chip)
  → 质量审查   (Reviewer：R0-R10 只审不修)
  → 确定修订   (Guard：只降级/删除，不新增)
  → 可信报告交付
```

| 主线节点 | 一句话 | 对应能力 |
|---|---|---|
| 需求进入 | 从自然语言抽取目标/竞品/焦点/意图 | Intake / Evidence Planner |
| 证据成池 | live/cache/mock 多源采集 + 覆盖率/质量审计 | Collector / EvidenceService |
| 事实成形 | 证据抽成 feature/pricing/persona/pain/SWOT/建议 | Analyzer |
| 报告出稿 | Markdown 报告，关键结论绑 chip | Writer / ReportView |
| 质量审查 | R0-R10 发现引用/覆盖/结构/语义风险 | Reviewer |
| 确定修订 | 只降级/删除/清理，不新增无证据内容 | Guard |
| 可信交付 | 报告 + Timeline + StageReport + 证据抽屉 | 前端工作台 |

**一句话总括**：这个项目不是「让大模型自动写一篇竞品报告」，而是把竞品分析做成一条**可信 Agent 流水线**——用户看到的不只是报告，还能看到每个 Agent 做了什么、哪些检查通过了、哪里需要人工复核、每条结论对应哪条原始证据。

## 2. 25′ 陈述脚本

| # | 章节 | 时长 | 主挣分维度 |
|---|---|---|---|
| 1 | 背景与定位 | 2′ | 业务价值 20% |
| 2 | 整体架构 · 多 Agent 协作 | 4′ | 多 Agent 协作 35% |
| 3 | 核心技术 · 关键架构设计 + 技术难点 | 8′ | 协作可信 35% + 技术深度 25% |
| 4 | 实机 Demo | 6′ | 全维度 |
| 5 | 业务价值量化 | 2′ | 业务价值 20% |
| 6 | 工程完整度 + 可观测 + 合规 | 2′ | 技术深度 25% + 合规 10% |
| 7 | 总结 + 演进 | 1′ | 答辩表达 10% |

**① 背景（2′）**：传统竞品分析慢（约 8 工时）、源窄、格式因人而异、**结论难溯源**。本系统一句话输入 → 结构化报告，每条结论一键点回原始证据。类比：面向竞品分析的 DeepResearch，但多做四件它不做的事——**采得更可信、结构更一致、每句可溯源、全程可审计**。

**② 整体架构（4′）**：六节点直线流水线（LangGraph 编排），理解为三阶段——意图识别 → 采集 → 处理，外加质检。三个要点：专职分工（六 Agent 各干一件事，三唯一 owner + AST 测试焊死边界）、结构化协作（传 `AgentState` 工单不聊天）、核心方法论（每阶段先定契约、再用可观测验证）。

**③ 核心技术（8′）**：见第 3 节（关键架构设计 + 技术难点）。这是全场最有含金量的部分，按「期望 → 观测发现问题 → 改进」讲。

**④ Demo（6′）**：输入一句话 → SSE 实时显示阶段/耗时 → 报告页（功能矩阵+SWOT+痛点+定价+质量徽章）→ 点 chip 弹原文/URL/可信度 → 质检前后对比 → 换行业关键词现场 LLM 发现竞品。现场用**本地**跑（能演 Playwright 抓定价），备 5 分钟录屏防断网。

**⑤ 业务价值（2′）**：见第 4 节表格。

**⑥ 工程 + 可观测 + 合规（2′）**：端到端链路完整；每个 Agent 的 Prompt/输入输出/Token 落 jsonl，按 run/stage 归因，现场可翻；三层降级断网也能跑；合规见第 8 节。

**⑦ 总结（1′，呼应开场）**：价值不在让大模型写报告，而在做成一条**可观测、可控、可降级、可换行业**的可信分析流水线。Demo 谁都能搭，我花精力的地方是把每个阶段都变得看得见、修得动。

## 3. 核心技术：关键架构设计 + 技术难点

### 3.1 五个关键架构设计（先讲 3′：设计决策 + 为什么）

| # | 关键架构设计 | 为什么 / 命中维度 |
|---|---|---|
| ① | **六节点直线 DAG + 单一 AgentState**：无环流水线，Agent 间传字段冻结的结构化工单（非自然语言对话） | 结构化协作 35% + 全程可观测可回放 |
| ② | **三个唯一 owner + AST 锁边界**：缺口判定 `evidence_gaps` / 采集执行 `evidence_service` / 结论强度 `guard` 各一 owner，AST 测试自动校验分析层不碰采集 | 边界无重叠靠代码守，不靠自觉（35%） |
| ③ | **「契约 + 可观测」方法论**：每阶段先定输入/输出契约，再用 `stage_quality.jsonl` 逐阶段验证实际产出 | 可观测 25%（项目灵魂） |
| ④ | **闭环下沉：直线 + 阶段内自检 + 确定性终门**：实测 54 run 打回仅 1 次 → 删带环打回状态机 | 闭环非伪 35% + 前瞻性 25% |
| ⑤ | **三层降级 + 泛化双路径**：采集 live→cache→mock、搜索 Brave→Tavily→DDG；竞品走 LLM 动态发现（主）+ YAML 兜底 | 降级 25% + 换行业 20% |

### 3.2 六个技术难点（再讲 5′：难点 → 方案 → 效果）

| # | 难点 | 方案 | 效果 |
|---|---|---|---|
| 1 | 长输出截断 + 倒推幻觉 | 两步式 facts→derivations + 三 section 并行 + 证据压缩 + quick_validate 自评估 | 截断率降；结论必挂事实，不足输出 unknown |
| 2 | 结论级溯源 | evidence_id 确定性 hash（编不出）+ `[SXXXXXXX]` chip + Reviewer R1/R9 校验 | 每句可点回原文，伪造引用被拦截 |
| 3 | 质检既可信又可终止 | 三层下沉 + 直线（54:1 实测驱动） | 闭环真实可触发且必收敛、无死循环 |
| 4 | 全量打回低效（20 分钟故事） | 闭环前置 + 定向补采（只补缺的那格）+ 策略阶梯换检索方法 + 轮次上限 | 20min → 约 4min、约 5× 提速且可终止 |
| 5 | 采集质量（无关信息 + 定价缺漏） | 5 维质量分 + 相关性硬门（≥70% 真提产品）+ Playwright SPA 渲染 | 少收无关、抓到真实档位价 |
| 6 | 并发提速但防串台 | ContextVar + CtxThreadPoolExecutor 隔离上下文 | 提速且跨 run 不串台（靠日志发现并修掉） |

> **两个工程框架值得在答辩时点名**：
> - **StageReport 四问**：每阶段同构回答「我产出了什么 / 我通过了吗 / 哪里坏了 / 成本多少」——前端 Timeline、后端日志、质量聚合读同一份数据。
> - **「谁的问题谁修」**：证据问题→EvidenceService（池内回捞优先，不足再定向外搜）/ 字段问题→Analyzer sanitize / 结论强度→Guard（清理降级，不新增）/ 格式→Writer+Reviewer。

## 4. 业务价值量化（vs 人工）

| 指标 | 人工分析 | 本系统 | 提升 |
|---|---|---|---|
| 分析耗时 | ~8 工时 | ~5 分钟 | 约 96× |
| 信息源类型 | 2-3 类 | 5+ 类 | 覆盖更广 |
| 结论溯源率 | 弱·不统一 | 85%+ | 每条可溯源 |
| 输出结构一致性 | 因人而异 | 100% 符合 Schema | 强一致 |
| 失败处理 | 重写 / 人工修 | 缺口定位后定向补证 / 修订 / 降级 | 可控可终止 |

> 说明：人工基线为行业经验估算；系统不替代分析师，而是生成可信初稿，提高资料整理、结构化对比、证据回查的效率。**自身迭代即实证**：质检从 20 分钟跑不完优化到约 4 分钟、约 5× 提速且可终止。

## 5. 性能优化（实测数字，最优配置已固化为代码默认）

| 优化项 | 手段 | 实测收益 |
|---|---|---|
| Thinking 分层 | 机械任务关隐藏思维链，深度推理保留 | 思维链占 43%-91% 输出 token；机械分类 24.8s→1.4s；端到端 -34% |
| Prompt 瘦身 | derivations 按 section 过滤证据 + 证据压缩（每类型≤5 条、摘要≤140 字） | prompt 体积 -23%~-38%；recommendations 74s→40s；盲评零掉分 |
| 多级并发 | Collector 多产品×适配器并发；Analyzer facts 三 section 并行 | feature 段墙钟约 8s（串行约 38s）；跨线程隔离不串台 |
| 池内回捞 | 缺口先回捞池内被 top-K 截断的存量证据，不足再外搜 | 省一次外搜的网络/token 成本 |
| 链路提速 | LLM 直连关代理；timeout 200s + 单次重试；搜索结果磁盘缓存 72h | 每次调用省约 10s 代理绕行 |

**端到端基线**：live 全链路 244.9s 产出含 200 条溯源 chip 的完整报告（Reviewer passed）。

## 6. 三个记忆点故事（讲故事比讲功能打动人）

1. **20 分钟跑不完** → 全量打回重抓 → 闭环前置 + 定向补采 + 策略阶梯 → 约 4 分钟。
2. **54:1 删打回** → 实测 54 run 跨节点打回仅触发 1 次 → 删带环状态机，改直线 + 确定性终门。
3. **定价缺漏是部署禁浏览器** → 线上免费档 512MB 禁 Playwright（headless Chromium 单实例 261MB、2 并发 634MB 必 OOM）→ 诚实降级标「不可得」，本地满血能演 SPA 抓真价。同一份代码两种形态，云端本身就是三层降级的真实演练场。

## 7. 高危问答三题（必背）

1. **闭环真伪？** → 三层下沉 + 54:1 + 现场前后对比 + 20 分钟故事。能打回，但实测打回极低频，于是下沉为更优解。
2. **Guard 怎么修 Reviewer 的发现？** → 诚实答「确定性重新对账、不逐条定向修，findings 仅计数」：清理不存在的 evidence_id、强对比缺双方证据则降级、basis 不足降 unknown、收敛过强表述。
3. **YAML 还是 LLM 发现竞品？** → LLM 主路径（动态发现最新有竞争力的竞品）、YAML 兜底（断网/无 key/Demo 种子）。

## 8. 合规声明

- **采集合规**：遵守 robots.txt 与服务条款；仅采集公开信息；source_bias / source_reliability 透明标注来源偏向。
- **数据隐私**：访谈/问卷数据脱敏；合成访谈明确标注 `synthetic=true`、`source_bias=synthetic`、可信度最低，**绝不冒充真实用户反馈**。
- **工具与模型**：LLM 经环境变量注入、API key 不入库；`.env`/key 均未提交仓库。
- **透明复核**：证据不足、低置信、来源偏向明显的结论，在报告和 StageReport 中透明标注，供用户重点复核。

---

> **一句话版本**：AI Competitive Radar 不是「自动写报告」的工具，而是一条可信竞品分析流水线——先规划证据，再采集补证，随后结构化分析、渲染报告、审查质量，最后由 Guard 做确定性修订；用户既看到报告，也看到每个 Agent 的执行过程和每条结论背后的原始证据。
