# 整体汇报脚本(25′ 陈述照着讲)

> 这是上台照着走的总稿。每节给出：**时长 · 主挣分维度 · 开口怎么讲 · 配什么画面**。
> 配套：`答辩方案.md`(七项材料备查)、`踩坑与优化迭代史.md`(技术细节底稿)、`需要你补充的清单.md`。

## 贯穿全场的一条主线(开场就抛，结尾再收)

> **"做这个项目，搭出一个能跑的 Demo 我很快就做好了。真正难的、也是我大部分精力花的地方，是把最终报告的质量做上去——而这要求我对每一个环节都完全可观测、可控。所以我做的核心，是把竞品分析拆成可审计的阶段，给每个阶段定义清楚该输出什么，再用可观测性去检查它实际输出了什么，发现偏差就修。这个项目的主角不是大模型，是可观测性。"**

记住这条，全场所有内容都挂在它上面。

---

## 1 · 背景与定位（2′） — 业务价值 20%

**开口**：
> "企业做竞品分析，传统方式很痛：一个分析师查一周、信息源就两三个、不同人写出来格式各异，最要命的是——你问他'这条结论哪来的'，他答不上来。我做的系统，输入一句话『分析 X 和 Y 在 Z 维度的差距』，自动产出结构化竞品报告，**每一条结论都能一键点回原始证据**。"

**类比 + 差异化**（重要，别被反将）：
> "它有点像面向竞品分析领域的 DeepResearch——但比通用 deep research 多做了四件它不做的事：**采得更可信、结构更一致、每句可溯源、全程可审计**。它不是写得更长，是质量可控。"

**画面**：首页 + 一份带 chip 的报告截图。

## 2 · 整体架构（4′） — 多 Agent 协作 35%

**开口**：
> "整个系统是一条六节点的直线流水线，用 LangGraph 编排。我把它理解成三个用户能感知的阶段——**意图识别 → 信息采集 → 信息处理**，外加一道质检。"

**讲三点**：
1. **专职分工**：六个 Agent 各干一件事（规划/采集/分析/撰写/质检/终审），职责边界用"三个唯一 owner"焊死，还写了 AST 测试自动校验分析层不碰采集——**边界无重叠**。
2. **结构化协作**：Agent 之间不聊天，传一份共享工单 `AgentState`（字段冻结的字典），每个往里填自己那栏——**结构化消息传递，非自然语言对话**。
3. **核心方法论**：每个阶段我都先定义"输入→输出契约"（该产出什么），再用可观测性验证它实际产出了什么。

**画面**：架构图（六节点直线 + 三阶段标注 + AgentState 横穿）。

## 3 · 核心技术 = 我的优化故事（8′） — 协作可信 35% + 技术深度 25%

> 这一节就是你的迭代史，按用户使用的阶段逐个讲"**期望 → 观测发现问题 → 改进**"。这是全场最有含金量的部分。

**开口**：
> "Demo 容易，质量难。下面我顺着用户使用的每个阶段，讲我观测到了什么问题、怎么修的。"

**① 意图识别**（30″）
> "为了真正能换行业，我没有把竞品写死在 YAML 里——YAML 会过时。我写了用 LLM 动态发现『当前最新、有竞争力的竞品』的逻辑，任何行业丢进来都能找到对的对手；YAML 只在断网/无 key 时兜底。"

**② 信息采集**（2′，**放 20 分钟那个故事**）
> "采集最早的版本有个大坑：质检发现缺东西，就**全量打回重抓**——只缺 Asana 一个定价，却把三个产品四类证据全重抓一遍；而且检索不到还会反复重试同一批词。最惨的一次，**跑了 20 分钟还没结束**。
> 我的解法是**把闭环前置、下沉到采集阶段内部**：采集出口就自检，缺了就**定向补采**——只补缺的那一格，不全量重抓；检索不到不重复，而是走**策略阶梯**换方法（站内→全网→中英别名→官网渲染→实在不行诚实标『不可得』），还有轮次上限。再加上 5 维质量分 + 相关性硬门，把无关信息挡在门外。**从 20 分钟跑不完，到现在一次约 4 分钟。**"

**③ 信息处理**（1.5′）
> "让大模型一次生成整篇报告，会 JSON 截断、还会『先想结论再倒编证据』。我把分析拆成**先抽事实、再做推导两步**，证据太多就压缩分桶，每条结论必须挂真实证据号——证据号是对内容做哈希算出来的，**编都编不出来**，证据不足就输出 unknown。每步还有自评估，发现问题当场确定性修复。"

**④ 质检演进**（1.5′，**规则复杂度失控的故事**）
> "质检我走过弯路。最早是教科书式的『打回-重跑-配额』——17 种问题类型路由到不同节点、各有重试配额、配额耗尽再降级，**规则复杂到难维护，控制流还带环有死循环风险**。但我实测发现，**54 次运行里跨节点打回只真正触发 1 次**——因为问题在阶段内部就自愈了。于是我把这套复杂状态机整个删掉，改成**一条直线 + 一个确定性终门**：质检只审、给问题打个『归谁』的标签，真正的修订交给终门基于证据确定性地清理降级，幂等、无环、修不掉就诚实降级。"

**⑤ 时间效率**（30″）
> "质量做扎实后，我专门做了一轮提速：采集器和分析的三个板块**并发执行**，**把大提示词拆成多步小问答**，再砍掉用不到的内容和隐藏思维链——推导从 74 秒降到 40 秒。并发最容易串台，所以我也是靠可观测日志发现并修掉了跨运行串台。"

**画面**：每个阶段配一张"观测指标截图/前后对比"。质检那段配"传统带环 vs 三层下沉直线"对比图。

## 4 · 实机 Demo（6′） — 全维度

**动线**（边操作边说）：
1. 输入一句话 → **SSE 实时显示走到哪个阶段、各阶段耗时**（可观测）。
2. 报告页：功能矩阵 + SWOT + 痛点 + 定价 + 质量徽章。
3. **点一个 chip → 抽屉弹出原文 / URL / 可信度**（溯源）。
4. **质检前后对比**：展示一处被质检抓到、被终门确定性修掉的内容（证明非伪闭环）。
5. 换一个行业关键词 → **LLM 现场发现竞品**跑起来（真泛化）。

> 现场用**本地**跑（能演 Playwright 抓定价）；备 5 分钟录屏防断网。

## 5 · 业务价值量化（2′） — 业务价值 20%

**开口 + 对比表**：
> "对比传统人工：耗时从约 8 工时降到几分钟，溯源率 85%+，结构 100% 符合 Schema。而且我自己迭代里就有实证——质检从 20 分钟跑不完优化到约 4 分钟，约 5 倍提速且**可终止**。"

## 6 · 工程完整度 + 可观测 + 合规（2′） — 技术深度 25% + 合规 10%

> "端到端链路完整：前端 → SSE 后端 → LangGraph 编排 → 本地存储。可观测上，每个 Agent 的 Prompt、输入输出、Token 都落 jsonl 日志，按运行和阶段归因，现场可翻。稳定性靠三层采集降级，断网也能跑。合规上：只采公开信息、遵守 robots、来源偏向透明标注，合成访谈明确标注是合成、绝不冒充真人，访谈数据脱敏。201 项测试全过。"

## 7 · 总结 + 演进（1′） — 答辩表达 10%

**收尾（呼应开场主线）**：
> "总结一句：这个项目的价值不在于让大模型写报告，而在于我把它做成了一条**可观测、可控、可降级、可换行业**的可信分析流水线。Demo 谁都能搭，我花精力的地方，是把每个阶段都变得看得见、修得动。后续我想接 RAG 提升证据相关性、把这些实测沉淀成持续的质量看板。"

## 讲述节奏提醒

- **开场和结尾都要点"可观测性是主角"** —— 这是你区别于"调个大模型出报告"的核心。
- **三个真实故事是记忆点**：20 分钟跑不完 / 54:1 删打回 / 定价缺漏是部署禁浏览器。讲故事比讲功能打动人。
- 核心技术节**从你自己的理解讲**（契约 + 观测 + 踩坑），不是背功能清单。
