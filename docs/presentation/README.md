# 答辩材料包 · 索引

> AI Competitive Radar（字节跳动 AI 全栈挑战赛 · Topic 3）答辩准备。
> 架构基线：**v3 M4 直线控制流 + 三层质检**（以当前代码为准，非旧 `final-submission.md` 的打回闭环）。
> 形式：25′ 陈述（背景 / 核心技术 / Demo）+ 20′ 问答。

---

## 一条主线（全场挂在它上面）

> **Demo 易、质量难。把报告质量做上去的前提，是对每个环节都完全可观测、可控——这个项目的主角不是大模型，是可观测性。**

---

## 五份文档怎么用

| 文档 | 是什么 | 什么时候用 |
|---|---|---|
| **`汇报脚本.md`** | 25′ 上台**照着讲**的总稿（每节：时长 / 挣分维度 / 开口怎么讲 / 配什么画面） | 答辩当天主稿；练习逐字过 |
| **`关键架构与技术难点.md`** | 核心技术节专稿：**5 个关键架构设计 + 6 个技术难点**（可直接转 PPT 页） | 做 PPT 核心技术页；被追问架构/难点时的底气 |
| **`答辩方案.md`** | 全量参考：25′ 脚本 + **七项材料正文** + 20′ 问答预案 + 答辩前检查清单 | 写提交材料、背问答预案、临场查漏 |
| **`踩坑与优化迭代史.md`** | 按用户使用阶段的**迭代史底稿**（期望→观测发现问题→改进） | 准备「我怎么一步步优化到现在」的叙事；技术细节查证 |
| **`需要你补充的清单.md`** | 只有你知道、代码里拿不到的信息（学校/专业、真实踩坑故事、最大收获等） | **优先填**，填完我把它融进上面四份 |

> 阅读顺序建议：先 `README` → `汇报脚本`（建立全局）→ `关键架构与技术难点`（吃透核心技术）→ `答辩方案`（背材料和问答）→ `踩坑与优化迭代史`（补血肉）。

## 三个记忆点故事（讲故事比讲功能打动人）

1. **20 分钟跑不完** → 全量打回 → 闭环前置 + 定向补采 + 策略阶梯 → 约 4 分钟。
2. **54:1 删打回** → 实测 54 run 打回仅 1 次 → 删带环状态机，改直线 + 确定性终门。
3. **定价缺漏是部署禁浏览器** → 线上免费档禁 Playwright → 诚实降级标「不可得」，本地能演 SPA 抓真价。

---

## 高危必背三题（问答环节）

1. **闭环真伪** → 三层下沉 + 54:1 + 现场前后对比 + 20 分钟故事。
2. **guard 怎么修 Reviewer 的发现** → 诚实答「确定性重新对账、不逐条定向修，findings 仅计数」。
3. **YAML 还是 LLM 发现竞品** → LLM 主路径、YAML 兜底。
