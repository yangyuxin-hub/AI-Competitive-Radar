# 竞品分析链路 · 优化总纲

> 配套阅读:[pipeline-stages.md](pipeline-stages.md)(各环 I/O 契约)。
> 本文是后续迭代的**总纲**——记录"往哪儿优化、为什么、按什么顺序"。契约定下界,本文定方向。

---

## 0. 统一思路

现在链路两头都偏死板:**进口**(检索)靠几条固定 query,**出口**(分析)把一堆证据一锅端给大模型让它自己找。优化方向是把两头都改活,中间用一个**证据检索层**串起来:

> **从「死板模板 + 一锅烩证据」→「先画像、按需检索、证据对齐」。**

四个环节的优化各自落到这条主线上:① 画像驱动检索(进口活)、② 按问题规划证据(进口准)、③ 按维度召回(中间串)、④ 可溯源 + 内容打回(出口实)。

---

## ① 意图澄清:画像驱动的自适应检索

**问题**:`_competitor_web_context` 只有 3 条固定 query(`{X} alternatives 2026` 等),搜到啥算啥,冷门行业/国产/新锐漏一大片。

**方案:先画像 → 按画像设计检索 → 缺口驱动二次检索**

1. **产品画像**(一次轻量 LLM):品类、核心任务(JTBD)、**用户分层**(个人/团队/企业;专业/小白)、竞争主维度。
2. **多角度 query 生成**(替单一模板):
   - 品类:`best {品类} tools 2026`(抓不知名新玩家)
   - **分层**:`{品类} for enterprise / for individual …`(不同人群竞品不同)
   - 颠覆:`AI-native {品类}` / `{品类} 国产替代`(召回新锐+国产)
   - 对比挖掘:`{X} vs`(评测站列竞品清单)
3. **多源发现**:接入 G2 / Capterra / alternativeto.net 等**维护竞品清单**的站,比零散搜索全。
4. **覆盖缺口驱动二次检索**:自检"有没有 AI 原生/国产玩家",缺哪类再补搜一轮(agentic)。

**预期**:竞品发现从"搜到几个算几个"→"按真实竞争格局系统性捞全"。

---

## ② 证据搜集:按问题规划证据类型 + 分层定价

**问题**:现在固定采 4 类证据,不随问题变;定价不分用户群体。

**方案**

1. **采什么证据随问题提前规划**(declarative evidence plan):
   - 定价问 → 各档价 + **计费模型**(按人/按量/包年)+ **每档对应哪类用户** + 隐性成本/折扣
   - 痛点流失问 → 吐槽 + 迁移故事 + 流失归因(权重压 UGC)
   - 功能对比问 → 官网采"有没有",UGC 采"好不好"
2. **分层定价抽取(P0)**:抓定价页时把每档**映射到用户群体**(`tier.segment` ∈ 个人/团队/企业),页面本就标了(Free=个人 / Team $X每人 / Enterprise=联系销售)。定价表直接回答"各类用户该选哪档、各家怎么收"。
3. **"采集完成"判定随问题变**:不再固定四类全覆盖,而是"这个问题需要的证据清单"逐项齐了才算完,缺项打回补(衔接 ④-2)。

---

## ③ 证据分析:清洗 → 相关性过滤 → 按维度召回(RAG 化)【大工程,单独排期】

**问题**:现在"每产品 top-8 证据一锅端给模型",信号稀、矩阵塌、易幻觉。

**方案:把"召回"做实——按维度点名取证据**

1. **清洗**:去重/近似去重(已有)+ **相关性门控**(滤掉跑题证据:讲别的产品/偏离焦点)。
2. **建证据索引**(向量 + 关键词,建一次)。
3. **按维度召回**:分析"实时协同"维度只检索真正提到协同的证据;分析痛点 P001 只召回相关吐槽——**只喂相关证据**。
4. **三重收益**:
   - 效果:每格由"真讲这维度的证据"撑 → 不塌、不幻觉(没召回到就老实 unknown)
   - 性能:prompt 变小 → 快、省 token
   - 可控:能看清"这结论召回了哪几条" → 好审核

**这是治本功能矩阵塌陷的正解**(比剪枝/打回更根本)。架构改动大,定方案后单独排期实现。

> 实现要点(排期时细化):evidence 索引存哪(内存/sqlite/向量库)、召回用 embedding 还是 BM25/关键词、每维度召回 top-k 与阈值、与现有 `_compact_evidence` 的关系(召回取代/前置于分桶)。

## ④ 结果处理:可跳转溯源 + 内容缺失也打回

**问题**:① chip `[S1A2B3C4]` 编号无意义,要可点链接 + 内容概要 ② 质检偏看格式,内容缺失没打回。

**方案**

1. **chip → 真溯源卡(P0)**:证据本带 `source_url` + `claim`(≤120 字概要)+ 原文片段。前端把 `[SXXXXXXX]` 渲染成**可点击链接**,悬浮/展开显示:**来自哪个网站、原文讲了啥、何时抓的、官网还是用户吐槽**。后端/前端数据现成(报告档案已含 raw_evidence),主要是前端解析 chip + 映射。
2. **质检加"内容覆盖"硬门(P0)**:现有 hard_gate 偏结构(R1/R4/R5),补一条**内容覆盖**:
   - 焦点维度是否每个产品都覆盖?
   - 定价是否每个产品都有(含分层)?
   - 痛点是否有足够**真实**(非合成)UGC 支撑?
   - 缺 → **打回检索**精准补,而非放过。

## 落地优先级(ROI 排序)

| 优先级 | 项 | 为什么先做 | 工作量 |
|---|---|---|---|
| **P0 快赢** | ④-1 chip 可跳转溯源卡 | 数据现成,纯前端+小接口,立竿见影提可信感 | 小 |
| **P0 高价值** | ②-2 分层定价 | 直接治定价缺失/不分群体 | 中 |
| **P0 高价值** | ④-2 内容覆盖打回 | 把"内容空"纳入质检红线 | 中 |
| **P1 治本** | ③ 证据索引 + 按维度召回 | 根治矩阵塌陷 + 提性能,架构级,单独排期 | 大 |
| **P1** | ① 画像驱动检索 | 竞品发现更全,收益递减、依赖外部源 | 中 |

**执行顺序**:先 P0 三项(见效快、风险低)→ 验证 → 再排期 P1 的 ③(RAG 召回)与 ①(画像检索)。
