# 功能树模型 + 决策导向报告结构 —— 设计 spec

> 项目：AI-Competitive-Radar（字节 AI 全栈挑战赛 Topic 3）
> 日期：2026-06-17 · 状态：设计已锁，待 review → 实现计划
> 关联：`docs/design-v2.2.md`、`docs/design-v3-draft.md`、`docs/pricing-model-jimeng.example.yaml`

## 0. 背景与目标

竞品分析的终点不是"看别人做了什么"，而是**辅助决策**。现有报告是 13 节按
**模块**平铺，止步于"事实层"。本 spec 做两件事：

1. **功能树升级为分析模型**：从一维「功能清单」升级成「加权三层 + 四层派生」。
   定价模型把价格数字加工成单位成本/性价比；功能树把功能清单加工成
   覆盖率/差异化/护城河/蓝海 —— 这才是它真正的分析价值。
2. **报告物理重排为决策四层**：事实层 → 比较层 → 洞察层 → 决策层，顶部加
   「决策摘要」。输入证据，输出决策，像一个"分析操作系统"，而不是报告目录。

设计铁律（沿用 CLAUDE.md 核心原则）：抑制假精确——无证据写 `?`/`unknown`，
护城河/蓝海有公式不拍脑袋，样本内差异点不绝对化，每条结论挂 `[SXXXXXXX]`。

## Part A · 功能树标准形态（功能模型）

### A.1 结构：加权三层

```
能力域 (capability_domain)         ← 带 weight，绑定 analysis_focus
  └─ 功能模块 (feature_module)
       └─ 功能点 (feature_point)   ← 叶子，承载所有事实字段
```

**能力域权重随 analysis_focus 重排**（这是功能树有决策价值的前提，不是固定表）：

```
焦点 = "视频生成质量与可控性"        焦点 = "小红书内容生产效率"
  视频生成能力  30%                    模板与素材生态  30%
  可控性        25%                    一键成片/批量   25%
  编辑与后处理  15%                    文案/脚本辅助   20%
  模板与素材生态 15%                   视频质量        15%
  商业化/协作/导出 15%                 商业化/发布链路 10%
```

权重来源：优先由 `analysis_focus` 经 LLM 提案 + 人工/config 复核，落 `config`
版本号（`feature_weight_version`，见 Appendix 口径锁定表），可复现。

### A.2 叶子（功能点）schema

```yaml
feature_point:
  id: str
  name: str
  products:
    <ProductKey>:
      support_status: supported | partial | unsupported | unknown
      depth_score: 1..5 | null          # 无证据写 null(渲染为 ?)，绝不编分
      evidence_level: official | third_party | user_review | inferred
      differentiator: bool              # 表述用"样本内差异点"，不说"独占"
      source_refs: [SXXXXXXX, ...]
```

**depth_score 评分口径（强制，写进 prompt 与 reviewer）**：

| 分 | 含义 |
|---|---|
| 1 | 仅有入口或基础能力 |
| 2 | 可用但限制明显 |
| 3 | 主流可用，效果稳定 |
| 4 | 质量/可控性明显优于多数竞品 |
| 5 | 专业级能力，形成明显工作流优势 |

仅当存在以下之一才给分：官方说明 / 实测结果 / 第三方评测 / 用户案例；
证据不足写 `null`。这条是防"看起来专业，其实在编分"的关键。

### A.3 派生层（确定性计算，不靠 LLM）

派生分三层，对应"比较 → 洞察 → 决策"：

#### 比较层派生

**`weighted_coverage`** —— unknown 处理规则（强制）：

```
分值: supported=1, partial=0.5, unsupported=0, unknown=排除
weighted_coverage_known_only = Σ(weight × score) / Σ(weight，仅 status≠unknown 的项)
evidence_coverage_rate       = (status≠unknown 的加权项) / (全部加权项)
```

> 理由：AI 产品信息缺失多是"抓不到证据"而非"没功能"。unknown 当 0 会惩罚
> 披露少的产品，导致结论偏差。故 unknown 不进覆盖率分子/分母，单独进
> `evidence_coverage_rate` 表达"这个结论建立在多少证据上"。
> 输出两个数：例「可灵 功能覆盖率 81%，证据覆盖率 76%」。

**`feature_winner`** —— winner 口径（强制，保守）：

```
打分 = weighted_sum(
  support_status_score, depth_score, evidence_level_score, differentiator_bonus
)
约束: 参与比较的产品都缺 depth_score 时，不允许强判 winner
输出:
  winner: <ProductKey> | tie | unclear
  reason: str
  confidence: high | medium | low
```

> 不允许只凭 support_status 判 winner（否则人人都是 ✓ → 都赢）。缺深度证据
> 时只能 `tie`/`unclear`。

**`differentiation_matrix`（样本内差异点矩阵）**：标注哪些能力在"本次样本
N 个产品中"只有某产品做到位。措辞强制带"样本内 N 个产品中"，不绝对化为
"独占"，除非全市场验证过。

#### 洞察层派生

**`product_archetype`**：由覆盖形态归纳 —— 全能型 / 专精型 / 工具型 / 平台型。

**`moat_candidates`（护城河）公式**：

```
护城河候选 = 高权重能力 × 高深度分 × 样本内差异点 × 难复制因素
难复制因素 ∈ {模型能力积累, 数据/素材生态, 工作流绑定,
              用户习惯迁移成本, 商业/渠道生态, 专业用户沉淀}
```

> 护城河不能只由"功能有无"推出，必须叠加难复制因素；迁移成本一项直接引用
> §4 用户画像。

**`whitespace_opportunities`（蓝海）公式**：

```
蓝海机会 = 高权重需求 × 当前覆盖不足 × 现有方案门槛高/成本高/学习成本高
```

> 不是"没人做所以能做"，而是"高价值需求未被低门槛解决"。

#### 决策层派生

**`action_recommendations`**：见 Part B §12，强制落到 Learn/Avoid/Attack。

### A.4 参考样例（即梦 / 可灵 / Runway，焦点=视频质量与可控性）

> 仅作形态示例；真实值以采集证据为准，无证据处写 `?`。

事实层（节选）：
```
能力域 A · 视频生成能力 [30%]
  文生视频     即梦 ✓(3) | 可灵 ✓(4) | Runway ✓(4)
  首尾帧控制   即梦 ✓(?) | 可灵 ✓(4) | Runway ◐(?)
  多镜头叙事   即梦 ✗   | 可灵 ◐(?) | Runway ✓(4)★
能力域 B · 可控性 [25%]
  运镜控制     即梦 ◐(?) | 可灵 ✓(3) | Runway ✓(5)★
  风格控制     即梦 ✓(4)★| 可灵 ◐(?) | Runway ✓(3)
```
比较层：`即梦 62% / 可灵 81% / Runway 78%`（known_only）；运镜 winner=Runway
(confidence high)，首尾帧 winner=可灵。
洞察层：即梦=工具/生态型，可灵=全能型，Runway=专精型；护城河 Runway 运镜
(5★+专业工作流绑定)、即梦 风格+剪映生态；蓝海=专业多镜头的小白化。
决策层：Learn 可灵首尾帧 / Avoid 别拼 Runway 专业运镜 / Attack 多镜头小白化。

## Part B · 决策导向报告结构 v3.1

### B.0 顶层骨架

```
0  决策摘要                 (每条结论带 confidence)
━ 事实层 FACTS ━
1  竞品格局
2  功能树·事实              (Part A 标准形态)
3  定价·事实                (只放事实，不放 archetype)
4  用户画像
5  技术能力                 (与功能树去重)
━ 比较层 COMPARISON ━
6  定位地图
7  功能覆盖与差距           (coverage_known_only + evidence_coverage + winner + 差异点矩阵)
8  定价同口径对比
━ 洞察层 INSIGHTS ━
9  功能定位 + 护城河 + 蓝海
10 商业模式逻辑             (pricing archetype 放这里)
11 SWOT
━ 决策层 DECISIONS ━
12 优先级建议               (12.1 Learn / 12.2 Avoid / 12.3 Attack)
━ 支撑 APPENDIX ━
13 证据覆盖 / 数据可得性 / 不确定性 / 口径锁定表
```

落地方式：**writer 物理重排**，章节真实按四层重新编号输出（不是逻辑分组）。

### B.1 逐节设计

**§0 决策摘要** `[新增]` —— 唯一"只读一页"，固定回答 5 个终极问题，每条
1-2 句 + chip + **confidence**：

```
每条结论:
  answer: str
  confidence: high | medium | low
  basis: evidence_count + evidence_level + unknown_fields
五问: 为什么成功 / 靠什么赚钱 / 护城河是什么 / 我们该学什么 / 我们该避开什么
```
例：「护城河是什么？Runway 专业可控性≈工作流护城河；即梦剪映生态=生态型
候选。置信度 medium：功能证据充分，但缺公开留存/付费转化数据。」

#### 事实层

**§1 竞品格局** `[已有]`：入选产品、定位一句话、体量/融资/团队。

**§2 功能树·事实** `[重写]`：Part A 加权三层，本节只呈现事实（support_status
/depth_score/evidence_level/differentiator/source_refs），不出覆盖率/winner/护城河。

**§3 定价·事实** `[重写, 去判断]` —— 只放事实字段，**archetype/strategy/商业
模式判断移到 §10**：
```
billing_options, normalized_monthly_price, credit_package,
unit_cost_image, unit_cost_video, quota_limit, billing_constraints, source_refs
```
**附带 bug 修复**：顶部价格表当 tier 仅有新 schema `billing_options` 时，
fallback 读其常规月价渲染，不再显示 `—`（当前 `_render_pricing` 第一表只读旧
`tier.price` 的问题，见探查记录）。

**§4 用户画像** `[提级为硬模块]`：人群分层 / 典型场景 / 核心痛点（原"用户
之声"归此）/ 付费意愿与门槛 / 迁移成本。迁移成本字段直接供 §9 护城河引用。

**§5 技术能力** `[新增模块]` —— 与功能树**去重规则（强制）**：

```
功能树回答: 用户能不能做某件事?
技术能力回答: 这件事背后的性能、质量、限制、模型能力到什么水平?
```

| 项目 | 功能树 | 技术能力 |
|---|---|---|
| 图生视频 / 首尾帧控制 | ✓ | ✗ |
| 生成速度 | ✗ | ✓ |
| 最大分辨率 | 可作功能叶子的限制 | ✓(主字段) |
| 最大时长 | 可展示 | ✓(硬指标) |
| 模型版本 / benchmark | ✗ | ✓ |

证据不足的技术指标标 `unknown`。

#### 比较层

**§6 定位地图** `[已有]`：二维象限 + 空白象限。

**§7 功能覆盖与差距** `[重写]` —— 确定性派生：`weighted_coverage_known_only`、
`evidence_coverage_rate`、`feature_winner`(product/tie/unclear + confidence)、
样本内差异点矩阵。

**§8 定价同口径对比** `[已有]`：unit_cost 横向比 + 口径限制（"元/秒 vs 元/条
不可直接比"如实声明）。

#### 洞察层

**§9 功能定位 + 护城河 + 蓝海** `[新增洞察]`：product_archetype、moat_candidates
（A.3 护城河公式）、whitespace（A.3 蓝海公式）。

**§10 商业模式逻辑** `[提出独立]`：**承接从 §3 移来的 pricing archetype + 定价
strategy + 商业模式判断**。放判断句，如"即梦低门槛积分=生态扩张而非单用户
价值最大化"。

**§11 SWOT** `[已有]`：聚焦 target；S/W 引用功能+技术事实，O/T 引用蓝海+护城河。

#### 决策层

**§12 优先级建议** `[强化]` —— 强制三子块 + 统一 schema：

```
12.1 Learn   学竞品已验证强项
12.2 Avoid   避开竞品高权重领先区
12.3 Attack  切入高价值空白区

每条建议:
  action_type: learn | avoid | attack
  action: str
  target_competitor: str
  evidence_refs: [SXXXXXXX, ...]
  priority_score: 0..100        # 按能力域权重×差距×证据强度算
  rationale: str
  risk: str
```

#### 支撑层

**§13 证据覆盖 / 数据可得性 / 不确定性 / 口径锁定表** `[已有 + 新增锁定表]`

**口径锁定表（新增，强制）**：

```
analysis_focus, selected_competitors, comparison_scope,
pricing_currency, pricing_period, unit_cost_formula,
feature_weight_version, unknown_handling_rule, generated_at
```

> 让报告自带"当时为什么这么算"的元信息，可复核、可复现。

## Part C · 实现影响（供 writing-plans 展开）

新增/改动（扁平单文件模块约定）：

- `src/feature_model.py`（新）：功能树确定性派生引擎，对偶 `pricing_model.py`。
  纯函数：`weighted_coverage` / `feature_winner` / `differentiation_matrix` /
  `derive_archetype` / `moat_candidates` / `whitespace`。同输入恒同输出。
- `src/feature_compare.py`（新，可选）：跨产品比较聚合，对偶 `pricing_compare.py`。
- `config/feature_weights.yaml`（新）：能力域权重 × analysis_focus，带 version。
- `analyzer`：功能树 facts 产出新 schema（三层 + 叶子字段）；调用 feature_model
  生成派生；§3 定价 facts 去掉 archetype 输出。
- `writer.py`：物理重排为四层 + §0 决策摘要 + §5 技术能力 + §10 商业模式逻辑
  + §13 口径锁定表；修 `_render_pricing` 顶表 fallback。
- `reviewer`：新增校验——depth_score 无证据必须 null；winner 缺深度证据必须
  tie/unclear；决策摘要每条必须带 confidence；样本内差异点措辞不得用"独占"。
- 测试：`feature_model` 单测（覆盖率 unknown 规则、winner 保守口径、护城河/蓝海
  公式）；writer 四层结构 golden 测试。

## Part D · 非目标（YAGNI）

- 不做全市场"独占能力"验证（只做样本内差异点）。
- 不做技术 benchmark 自动跑分（只采集已公开指标）。
- 不重构无关模块；feature_weights 先支持 demo 两个焦点，不做通用权重学习。
