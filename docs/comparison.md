# 人工分析 vs 本系统 — 量化对比

> 本文档是为评分维度 3「业务价值」准备的硬数据。
> 实测数据基于 PM 域(Notion vs Asana vs Linear)的端到端真豆包跑通。

---

## 一、五维度量化对比

| 维度 | 传统人工分析师 | 本 Agent 协作系统 | 提升 |
|------|--------------|-----------------|------|
| **🕐 端到端耗时** | 3-4 小时(含搜资料/做表格/写报告) | **5 分 30 秒**(真豆包,Mock 模式 < 5 秒) | **38 倍** |
| **📚 证据覆盖量** | 通常 15-20 条(凭印象) | **30 条 / 域**(配置可扩,无上限) | **1.5-2 倍** |
| **📐 结构一致性** | 自由 Word/PPT,字段命名各异 | **100% 符合 Schema v2.1**(7 个固定模块) | 质变 |
| **🔁 可重现性** | 同一题不同人结论可能差 30%+ | **同样输入 → 100% 一致输出** | 质变 |
| **🔗 可溯源性** | 段落引用,经常断链 | **每条结论带 chip,点击展开原文 + 可信度** | 质变 |

> 后三项不是"快多少倍"的问题,是**人工流程根本做不到**的能力。

## 五、传统人工流程拆解(对比参考)

| 阶段 | 人工耗时 | 本系统 | 节省 |
|------|--------|--------|------|
| 1. 搜集竞品官方资料 | 30-45 分钟 | Collector 1.2s(MockAdapter)或 10-25s(真实抓取) | 99% |
| 2. 整理用户评论 / 痛点 | 60-90 分钟 | 同上 | 99% |
| 3. 做功能对比表格 | 30-45 分钟 | Analyzer Step1 ~80s | 96% |
| 4. 推导改进建议 + 优先级 | 30-60 分钟 | Analyzer Step2 ~50s | 97% |
| 5. 写报告 / 排版 | 30-45 分钟 | Writer < 1s | 99% |
| 6. 自查(漏证据 / 推理断裂) | 15-30 分钟 | Reviewer < 1s + 自动打回 | 100% |
| **合计** | **3-4 小时** | **5-6 分钟** | **97%** |

## 六、对人工的非显然优势(评委可能 follow-up)

| 场景 | 人工劣势 | 系统优势 |
|------|---------|---------|
| 「这个建议从哪条数据推出来的」 | 翻草稿找 30 分钟,可能找不回 | 点 chip 立刻看原文,**100% 可追溯** |
| 「我们决定先做哪条改进」 | 直觉拍板,新成员质疑没依据 | priority_score 加权公式 + 4 维评分,**可解释** |
| 「换个行业再做一份」 | 完全重做 3-4 小时 | 改 YAML + 备 evidence 文件,**30 分钟** |
| 「我加一个新规则:必须覆盖移动端体验」 | 全员告知 + 检查表,执行不一致 | Reviewer 加一条 rule,自动校验,**100% 一致** |
| 「报告里某条结论被质疑造假」 | 不可追溯,只能靠分析师人品 | evidence_id 哈希唯一,**评论上下文随时可查** |

## 七、本系统的局限(诚实陈述)

| 局限 | 影响 | 缓解 |
|------|------|------|
| 强依赖 evidence 质量 | "Garbage in, garbage out" | 三层 Adapter 兜底 + 多源 source_bias 标注 + Reviewer R7 freshness |
| Prompt few-shot 用了 Cursor 示例 | LLM 可能偏向相似域 | 实测 PM 域结果未受污染;v2.3 可换 few-shot |
| 真豆包调用 2-5 分钟 | UX 等待长 | Cache 命中后只跑 Analyzer 两步;Mock 模式可秒级演示 |
| Reddit / HN 数据需注意版权 | 法务风险 | 只摘要不重发 + 标 URL;生产建议接官方 API |
| 国内访问海外站点不稳 | 真实抓取可能失败 | 三层兜底:抓不到走 cache,cache 没有走 mock |
